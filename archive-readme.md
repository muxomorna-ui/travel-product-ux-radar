# Постоянный архив тревел-радара

`radar.sqlite` хранит материалы по стабильным ID, версии содержимого, источники, обращения к ним и помесячный журнал покрытия. Повторный импорт не дублирует неизменённые материалы. Доказательства остаются в каталогах выпусков: их нельзя удалять.

Обновление после сборки выпуска (из корня проекта):

```sh
/opt/homebrew/bin/python3.11 travel-radar/archive/manage.py sync travel-radar/runs/2026-10-28-ytd
/opt/homebrew/bin/python3.11 travel-radar/archive/manage.py daily-plan --day 2026-10-29
```

Второй шаг создаёт `daily-plan.json` с заданиями по источникам, сгруппированными по типу. Это план для следующего сбора, не выполненный сбор и не автоматизация по расписанию.

## Ежедневное пополнение

1. Проверять новые публикации за день (либо после последней успешной ежедневной проверки), не повторять обход января–октября.
2. Читать найденные материалы, разделять дату публикации и запуска. Сопоставлять с существующими ID и URL; дополнения к старой истории сохранять как новую версию либо связанный этап.
3. Сохранить доказательства, события и исход проверки в выпуск; импортировать через `sync`.
4. Только после успешного чтения заданного дневного интервала и сохранения результата записать курсор источника в `cursors`. При ограничении доступа курсор не продвигать. Сейчас курсоры пусты: завершённых ежедневных обходов ещё нет.

Незавершённая проверка старых архивов — отдельная очередь `monthly_coverage`. `pending` не означает «событий нет», `partial` — отдельные материалы, `index_scanned` — индекс отдельного раздела с выборочным чтением статей. Полного исторического покрытия пока нет. Ежедневный сбор не закрывает эти пробелы автоматически.

## Проверка достоверности и типы событий

После повторного чтения материалов в выпуске сохраняются `link-audit/`, `verification-review.json` и `event-taxonomy.json`. Результат открытия страницы не равен подтверждению факта. `reliability.confirmed` означает подтверждённое опубликованное сообщение в пределах оговорок карточки; испытание интерфейса фиксируется отдельно. Недоступный источник, неподтверждённые даты и условия оставляют карточку со знаком вопроса. Нельзя снимать его только из-за успешного HTTP-ответа.

В постоянной базе журнал ссылок хранится в `link_checks`, а решения и типы событий — в версиях событий. При ежедневном импорте сохранять стабильные ID, конкретные причины неопределённости и найденные замены ссылок. Заменённые адреса остаются в `superseded_sources`, не стираются.
